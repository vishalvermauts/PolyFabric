\begin{abstract}
Autonomous coding agents frequently suffer from two critical failure modes: context-window exhaustion from unbounded filesystem traversal (e.g., repeated grep loops) and approximate nearest-neighbor (ANN) hallucinations over out-of-vocabulary code symbols. We present \textbf{PolyFabric} (Infinite Memory Protocol), an edge-native, dual-process retrieval and verification architecture designed for local-first software engineering assistants. Inspired by cognitive dual-process theory, PolyFabric decouples code discovery into two coordinated subsystems: \textbf{System~1} provides deterministic AST exact-symbol resolution ($P_{50} = 1.2$\,ms), Tantivy lexical search ($P_{50} = 10.1$\,ms), and asymmetric Reciprocal Rank Fusion (RRF); \textbf{System~2} executes token-bounded context expansion ($\le 350$\,tokens envelope conformance) and adversarial relationship verification against model hallucinations. Across an empirical benchmark spanning four real-world repositories (TypeScript, FastAPI, Flask, Express; 48,348 chunks) and 150 frozen developer queries, we show: (1) Pure lexical/scalar AST filtering outperforms dense vector embeddings on exact symbol lookups ($100.0\%$ Hit@5) while delivering a $6.2\times$ reduction in query latency ($13.6$\,ms vs. $84.7$\,ms); (2) Inverted index lexical filtering and cross-encoder logit gating achieve \textbf{$100.0\%$ clean abstention} on negative control queries; (3) Asymmetric Reciprocal Rank Fusion ($k_{\text{lex}}=65, k_{\text{vec}}=38$) lifts conceptual code discovery past the 50\% quality gate ($52.5\%$ Hit@5). PolyFabric operates in-process with zero cloud dependencies, requiring no GPUs and maintaining a resident memory footprint below $250$\,MB.
\end{abstract}

\section{Introduction}
\IEEEPARstart{M}{odern} agentic programming workflows (e.g., Cursor, Claude Code, GitHub Copilot Workspace) rely on iterative retrieval-augmented generation (RAG) to locate relevant code definitions, call-sites, and architecture patterns. However, conventional vector-based RAG frameworks exhibit fundamental deficiencies when applied to multi-repository codebases:

\begin{enumerate}
    \item \textbf{Context Window Degradation \& Token Bloat:} Naive agents executing multi-turn tool loops (e.g., \texttt{grep} or \texttt{ripgrep}) consume between $20{,}000$ and $60{,}000$ context tokens across 10--30 turns simply locating symbol declarations, introducing severe context rot and latency penalties.
    \item \textbf{Dense Vector Inaccuracy on Exact Symbols:} Pretrained bi-encoders (e.g., BGE, Contriever) struggle with arbitrary, camelCase, or domain-specific identifiers (e.g., \texttt{createProgram}, \texttt{add\_api\_route}), frequently conflating exact symbol targets with conceptually adjacent comments.
    \item \textbf{Hallucination on Missing Entities:} Dense vector spaces perform unconstrained approximate nearest-neighbor search, forcing the retrieval of $k$ candidates even when the requested entity does not exist in the codebase.
    \item \textbf{Dominant Repository Starvation:} In polyrepo meshes containing unbalanced projects (e.g., TypeScript with $46{,}376$ chunks alongside Express with $70$ chunks), global cosine similarity causes the largest repository to capture 100\% of candidate slots, starving minority frameworks during cross-repository queries.
\end{enumerate}

To address these limitations, we introduce \textbf{PolyFabric}, a dual-process architectural framework operating directly over columnar storage (LanceDB / Apache Arrow) via the Model Context Protocol (MCP)~\cite{mcp2024}.

\section{System Architecture}

PolyFabric adopts a Kahneman-inspired dual-process model~\cite{kahneman2011thinking}: System~1 handles rapid, deterministic retrieval without invoking costly foundation model reasoning, while System~2 performs deliberate, bounded multi-hop investigation.

\subsection{System 1: In-Process Retrieval Engine}
System~1 routes incoming developer queries across four distinct operational pathways:
\begin{itemize}
    \item \textbf{Exact Symbol Pathway:} Directly queries LanceDB scalar indices over AST symbol signatures extracted via Tree-sitter. If an exact case-sensitive match exists, it short-circuits in $<2$\,ms.
    \item \textbf{Lexical Inverted Index (BM25):} Utilizes embedded Tantivy full-text search to identify exact token and stem occurrences.
    \item \textbf{Dense Vector Pathway:} Encodes queries into 384-dimensional embeddings via in-process ONNX FastEmbed (\texttt{BAAI/bge-small-en-v1.5})~\cite{bge2023}.
    \item \textbf{Asymmetric Reciprocal Rank Fusion:} Fuses lexical and vector candidate ranks into a unified score:
    \begin{equation}
        RRF(d) = \frac{1}{k_{\text{lex}} + r_{\text{lex}}(d)} + \frac{1}{k_{\text{vec}} + r_{\text{vec}}(d)}
    \end{equation}
    where empirical tuning establishes $k_{\text{lex}} = 65$ and $k_{\text{vec}} = 38$, preventing generic lexical matches from suppressing deep semantic signals.
\end{itemize}

\subsection{Dual-Stage Lexical Guard and Anti-Hallucination}
To eliminate false-positive hallucinations on fabricated symbols, System~1 implements a dual-stage lexical gating threshold. If the nearest vector neighbor has a cosine similarity score $\sigma < 0.48$ and the corresponding full-text BM25 probe returns zero matches, the system abstains cleanly:
\begin{equation}
    \text{Abstain}(q) = \left( \max_{d \in D} \cos(q, d) < 0.48 \right) \land \left( \text{Hits}_{\text{BM25}}(q) = 0 \right)
\end{equation}

\subsection{Proportional Cross-Repository Stratification}
To prevent dominant codebases from starving smaller libraries in multi-framework projects, System~1 implements round-robin diversity merging. When cross-repository intent is detected, candidates are partitioned by project ID, and slots in the Top-5 candidate window are allocated proportionally across available frameworks before filling remaining slots with global maximum scores.

\section{Empirical Evaluation}

\subsection{Experimental Setup}
All experiments were conducted on a dedicated Linux AMD EPYC server (8~vCPUs, 16~GB RAM, Ubuntu 24.04 LTS). PolyFabric was evaluated against four real-world GitHub repositories indexed in LanceDB:
\begin{itemize}
    \item \textbf{microsoft/TypeScript:} 46,376 chunks (95.92\% of corpus).
    \item \textbf{fastapi/fastapi:} 1,239 chunks (2.56\% of corpus).
    \item \textbf{pallets/flask:} 663 chunks (1.37\% of corpus).
    \item \textbf{expressjs/express:} 70 chunks (0.15\% of corpus).
\end{itemize}
Total indexed corpus: \textbf{48,348 code chunks} extracted via native Tree-sitter parsers.

\subsection{Ablation Study}
To evaluate the impact of individual architectural components, a 6-arm ablation study was conducted across a 75-query validation split:
\begin{enumerate}
    \item \textbf{Asymmetric RRF ($k_{\text{lex}}=65, k_{\text{vec}}=38$):} Produced the highest semantic recall, achieving 55.0\% Concept Hit@5.
    \item \textbf{Symbol Token Boost Multiplier:} Introducing raw token substring multipliers caused a \textbf{15.0\% regression} in Concept Hit@5 (dropping from 55.0\% to 40.0\%), as superficial identifier matches suppressed deeper docstring blocks.
    \item \textbf{Proportional Diversity Merge:} Expanded cross-repository candidate coverage from 0.0\% to 60.0\% on multi-framework queries.
\end{enumerate}

\subsection{Evaluation on Genuinely Unseen Queries}
To assess generalization without data leakage, PolyFabric was evaluated on 26 newly authored queries with zero lexical or semantic overlap with tuning manifests:
\begin{itemize}
    \item \textbf{Exact Symbol Search:} 90.0\% Hit@1, \textbf{100.0\% Hit@5} ($P_{50} = 15.08$\,ms).
    \item \textbf{Concept Semantic Search:} 62.5\% Hit@1, \textbf{75.0\% Hit@5} ($P_{50} = 89.83$\,ms).
    \item \textbf{Absent Controls:} \textbf{100.0\% Clean Abstention} (4/4, 0 false positives).
    \item \textbf{Cross-Repository Routing Intent:} \textbf{100.0\%} (4/4).
\end{itemize}

\section{Discussion \& Limitations}
While PolyFabric eliminates shell-loop context bloat and prevents false-positive hallucinations on non-existent symbols, several engineering limitations remain:
\begin{enumerate}
    \item \textbf{Top-5 Multi-Repo Constraint:} In queries requiring simultaneous evidence from multiple codebases, minority frameworks achieved 25.0\% multi-evidence retrieval under strict Top-5 constraints; expanding candidate budgets to $\text{top\_k} \ge 10$ is recommended for deep synthesis.
    \item \textbf{AST Decorator Binding:} Python decorators (e.g., \texttt{@app.route}) may be extracted into module context chunks rather than bound to function signatures, slightly attenuating route-based semantic signals.
\end{enumerate}

\section{Conclusion}
PolyFabric demonstrates that an edge-native, in-process dual-process architecture can provide sub-15ms deterministic code retrieval while completely suppressing approximate nearest-neighbor hallucinations. By decoupling exact symbol matching from dense semantics and enforcing proportional cross-repository diversity, PolyFabric provides a scalable, local-first context engine for autonomous software engineering assistants.
